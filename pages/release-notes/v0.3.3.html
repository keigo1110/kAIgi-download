kAIgi 0.3.3

Textワークスペースを、論文を実際に読み進められる道具にしました。ページと対訳が両方向に行き来できるようになり、章立てと要点を出せるようになり、待ち時間が減りました。

  • PDFの段落をダブルクリックすると、右の対訳がその段落へ移動します。これまでは対訳からページへ跳ぶことしかできませんでした。跳ぶのは操作した側と反対のペインだけなので、読んでいた位置は動きません。
  • 右ペインで「対訳」と「構造」を切り替えられます。「構造を生成」を押すと、段落ごとの1行要点と、文書全体の背景・課題・手法・評価方法・結果・限界・貢献・Claimをこのマシンの中だけで作ります。開いただけでは生成しません。
  • 要点は章・子章・孫章ごとに畳んで読めます。要点をクリックすると本文とページがその位置へ移動します。
  • 本文の読み直しで段落の区切りが変わった要点は、古い内容を現在のものとして見せずに表示を取り下げます。
  • 構造の生成にはmacOS 26以降とApple Intelligenceが要ります。使えない環境では構造ペインがその条件を述べ、リーダー・対訳・コメントは通常どおり使えます。アプリの最低要件はmacOS 14のままです。
  • 見出しの判定を、行の高さではなく実際の活字の大きさで行うようにしました。これまでは上付きの脚注番号や総和記号、表の単位が1つ入るだけで本文が見出しとして扱われていました。実際の論文で、見出しとして拾われる箇所が71件から37件（その論文が実際に持つ見出しの数）になりました。
  • 著者名・所属・メールアドレスと参考文献を、本文と分けて扱うようになりました。表示は残したうえで翻訳と要約の対象から外します。2行にわたるタイトルや見出しも、途中で切れずに1つにまとまります。
  • 段組みや改ページで切れていた段落を繋ぐようにしました。実際の論文で、文の途中から始まってしまう段落が148件中30件（2割）ありましたが、114件中3件になりました。数式と表の数値も本文から外し、断片が翻訳されないようにしました。
  • この変更で、取り込み済みの文書は次に開いたときに一度だけ本文を取り出し直します。コメントは引用文と位置から元の箇所に付き直し、区切りが変わった箇所の訳は裏で訳し直されます。
  • 文書を開くと全文の翻訳を裏で進めます。一度読んだ文書は、次に開いたときに待ち時間がありません。読んでいる箇所は常に最優先で、裏の翻訳が追い越すことはありません。
  • 訳文が1文ずつ届いた順に出るようになりました。これまでは24文が揃うまで1文も表示されませんでした。翻訳の初回準備も先に済ませるため、開いた直後の待ちがなくなりました。
  • 進行表示を見直しました。スピナーは自分が待っているときだけ出て、裏の全文翻訳は訳済みの件数を控えめに示します。別の文書に切り替えると裏の翻訳はその場で止まります。
  • kaigi documents コマンドから、要点・見出しの深さ・文書全体の読み筋を読めます。生成できるのは本人だけで、AIは読むだけです。
  • CLIがschema v3の文字起こしを正しく扱えるようになりました。kaigi capabilities で対応schemaとコマンドを確認でき、kaigi --help / -h / コマンド別helpもJSONで使えます。新しいschemaに古いCLIで遭遇したときは、壊れたJSONではなくCLI更新が必要だと案内します。

翻訳も要約もこのMacの中だけで処理し、文書の本文が外部へ送られることはありません。要約にはmacOSに内蔵されたモデルを使い、追加のダウンロードは要りません。翻訳で未導入の言語を使う場合のみ、macOSがApple管理の言語モデルの取得を確認します。

取り込んだPDFの元ファイルは変更も削除もしません。生成した構造は文書ごとに保存され、文書を削除すれば一緒に消えます。既存の録音・Visualデータと保存形式は引き続き読み込めます。
