kAIgi 0.4.9

RELEASE / 0.4.9

端末内AIを有界に。根拠を監査可能に。Bound local intelligence. Audit the evidence.

kAIgi 0.4.9は、Macの負荷と録音を優先するLocal AI、ページ別PDF補修、最大3つの可視検索語、5.6 Sol等へ渡せる根拠パッケージを追加し、録音・更新・配布の復旧境界も強化します。kAIgi 0.4.9 adds recording-aware Local AI, per-page PDF repair, up to three visible search queries, and auditable evidence packages for a user-selected frontier model, while strengthening recording, update, and release recovery boundaries.

  • Version 0.4.9
  • Build 43
  • macOS 14+
  • Apple Silicon

録音を優先しながら、Gemmaを賢く使うUse Gemma intelligently while recording stays first

1つの資源ガバナが録音、メモリ負荷、発熱、低電力モードを確認し、重い任意処理を開始前に延期します。進行中の物理処理を途中で二重実行せず、高メモリMacでは有限時間warmに保ちます。One resource governor considers recording, memory pressure, thermal state, and Low Power Mode before admitting optional heavy work. It does not overlap a retry with unfinished physical work, and keeps Gemma warm for a finite memory-tiered interval.

ハーネスv3は2回までの生成上限を維持し、名前、数値、単位、範囲、日付、否定、不確実性、増減方向、因果を根拠へ照合します。競合値は分け、検証できない主張は公開しません。Harness v3 keeps the two-generation ceiling while checking names, numbers, units, scope, dates, negation, uncertainty, direction, and causality against evidence. Conflicting values remain separate and unsupported claims are not published.

PDFの不足ページだけを補修するRepair only the PDF pages that need it

text layerをページごとに診断し、画像と文字が混在するPDFでも不足ページと理由を示します。OCRは自動開始せず、明示操作で推奨ページだけをApple Visionで端末内処理し、正常なtext layerを置き換えません。kAIgi diagnoses each page's text layer so a mixed PDF can expose the pages and reasons that need repair. OCR never starts automatically; an explicit action runs Apple Vision only on recommended pages without replacing healthy text.

固定されたtext／image／sparse／mixed／malformed PDFコーパスで抽出と構造入力を回帰確認できます。結果は従来どおり対訳、構造、コメント、Recall、CLIへ渡ります。A fixed text, image, sparse, mixed, and malformed PDF corpus protects extraction and structure input from regressions. Accepted text continues into translation, Structure, comments, Recall, and the CLI.

検索の幅を広げても、送信語は隠さないBroaden research without hiding outbound queries

Deep Researchは主検索語と補助語最大2件を、期間・ドメインとともに送信前に表示・編集します。検索は順番に実行し、一部失敗でも成功結果を残し、同じURLを全検索語間で重複除去します。Deep Research shows and lets you edit the primary query and up to two supplemental queries together with time and domain scope. Queries run sequentially, partial success is preserved, and duplicate URLs are removed across the combined results.

hidden queryや結果ページ本文の自動取得はありません。DuckDuckGo／Wikipediaへ送る値、成功件数、provider状態は確認できます。There are no hidden queries and no automatic result-page fetches. The UI exposes what goes to DuckDuckGo and Wikipedia, successful-query count, and provider status.

5.6 Sol等へ、同じ根拠を監査可能に渡すHand the same evidence to a frontier model, auditably

kaigi evidence-packageはAudioとTextを有界検索し、根拠ID、完全性、SHA-256を含むJSONとreceiptをローカル作成します。元ファイルpath、bookmark、PDF binaryは含みません。kaigi evidence-package performs bounded Audio and Text retrieval and writes local JSON plus a receipt with evidence IDs, completeness, and SHA-256 hashes. It excludes source paths, bookmarks, and PDF bytes.

CLIはモデルを起動せず外部送信もしません。パッケージにはprivate/untrusted textが含まれるため、選択した外部モデルへ渡す操作は利用者が別途許可します。The CLI neither launches a model nor transmits the package. Because it contains private, untrusted source text, sending it to a selected external model requires separate user authorization.

保存・復旧・更新をfail-closedにするFail closed across storage, recovery, and updates

録音はApplication Supportへ保存し、旧Documentsライブラリをno-overwriteで移行します。議論ログ、音声最終化、起動時回収、将来schemaのread-only表示を強化しました。Recordings now live in Application Support, with a no-overwrite migration from the legacy Documents library. Discussion checkpoints, audio finalization, startup recovery, and read-only handling of future schemas are stronger.

clean／dirty trial証跡を分離し、notarizationはKeychain profileだけを使います。正式版の自動更新はSparkleの同意後だけ、開発版は無効です。新しい認証済みAgent Skillも古い同梱版から保護します。Clean and dirty trial evidence are distinct, notarization is Keychain-profile-only, release automatic checks follow Sparkle consent, development checks stay off, and a newer authenticated Agent Skill is protected from bundled downgrades.
