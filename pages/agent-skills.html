CLI / SKILLS

会議と文献を、次の作業へ。 Take meetings and papers into the next task.

kAIgi CLIは録音・文字起こし・抽出済みの文献本文をローカルで扱います。0.4.11のcontract v7では、追跡可能な根拠packageに加え、外部エージェントが作った文字修正を全差分reviewとSHA-256で確認してから反映できます。 The kAIgi CLI works locally with recordings, transcripts, and extracted paper text. Contract v7 in 0.4.11 adds review-bound transcript postprocessing with complete diffs and SHA-256 acknowledgement alongside traceable evidence packages.

まず設定でインストール Install from Settings first

1. CLIをインストール 1. Install the CLI

kAIgiの設定にある「Codex / Claude Code連携」でCLIをインストールします。保存先も同じ画面で確認できます。 In kAIgi Settings, open “Codex / Claude Code Integration” and install the CLI. The destination is shown there.

2. Skillsをダウンロード／更新 2. Download / Update Skills

同じ画面の一つのボタンで、利用可能なCodex／Claude Code向け保存先をまとめて更新します。保存先ごとの状態は確認できますが、製品ごとのインストール操作は必要ありません。 One button updates every available Codex and Claude Code destination. You can inspect each destination's status without managing separate install actions.

3. Skillsを呼び出す 3. Invoke the Skill

CodexではSkill名を指定し、Claude Codeでは /kaigi を入力します。 Name the Skill in Codex; type /kaigi in Claude Code.

コマンドを覚える前に、5つの使い方から選べます。Agent Skillが安全な手順を案内し、正式データへ反映する操作は検証後に明示して行います。 Choose from five practical workflows before learning any commands. The Agent Skill guides the safe steps, and canonical data is changed only after validation and an explicit apply.

01 / FIND

録音を横断して、必要な瞬間を探す Find the moment across your recordings

タイトル・日時・文字起こしを一覧・検索し、候補を話者・時刻・確度つきで確認できます。探す段階では正式データを変更しません。 List and search titles, dates, and transcripts, then inspect a candidate with speakers, timing, and confidence. Discovery never changes canonical data.

list · search · inspect

02 / REFINE

低確度から全文まで、2段階で整える Refine low confidence first, then the full context

作業用コピーで誤認識を直し、話者・時刻などは保ったまま文字だけの変更か検証します。別の更新が先に入っていれば、古いコピーとして安全に停止します。 Correct recognition errors in a working copy, verify that only text changed, and preserve speakers and timing. A stale copy stops safely if another update landed first.

export · validate-transcript · apply-transcript

03 / STRUCTURE

会話を、決定と次の一手が見える議論ログへ Turn conversation into a decision-ready discussion log

全文と発話列を保ったまま議題を構造化し、決定・アクション・未解決事項を追える形にします。スキーマと元発話の一致を検証してから原子的に反映します。 Structure topics while retaining the full transcript and utterance sequence, so decisions, actions, and open questions stay traceable. Schema and source identity are validated before atomic publication.

discussion-log export · validate · apply

04 / TRANSCRIBE

手元の音声を、その場で文字起こし Transcribe an audio file where it already lives

M4Aなどの外部音声をこのMac上で文字起こしし、独立したJSONとして保存します。kAIgiの録音一覧には勝手に追加しません。 Transcribe an external audio file such as M4A on this Mac and save a standalone JSON result. It is never added to the kAIgi recording library automatically.

transcribe

05 / LITERATURE

会議と文献から、執筆の根拠を集める Gather writing evidence from meetings and papers

統合 context で会議録と抽出済み文献を一度に探し、発話時刻・ページ・段落・本文ハッシュつきの根拠を渡します。CLIは回答やレビュー本文を生成しません。 Unified context searches transcripts and extracted papers together and returns evidence with utterance timing, page, passage, and source hashes. The CLI does not generate an answer or literature review.

context · evidence-package · documents context · recordings inspect

互換性を確認 Check compatibility

利用できるコマンドと文字起こしschemaの対応範囲をJSONで確認します。kaigi --help と kaigi help <command> では、全体またはコマンド別の使い方を確認できます。schemaが新しすぎる場合は、kAIgiの設定で「CLIを更新」を実行してください。 Reports the available commands and supported transcript-schema range as JSON. Use kaigi --help or kaigi help <command> for global or scoped usage. If the schema is newer than the CLI supports, choose “Update CLI” in kAIgi Settings.

kaigi context "embodied agency" --limit 6 --max-evidence-per-source 6 --best-effort

会議と文献を一度に探す Search meetings and papers together

保存済みの会議録と抽出済み文献を横断し、正確な文字起こし区間とPDF段落を一つの有界なJSONへまとめます。各候補には元データのSHA-256、位置、一致語、次に深く読むためのコマンドが付きます。completeness.recordings と completeness.documents を確認してから、不在を判断してください。 Searches saved meetings and extracted papers and returns exact transcript intervals and PDF passages in one bounded JSON response. Each candidate includes source SHA-256, location, matched terms, and the next command for close reading. Check completeness.recordings and completeness.documents before concluding that evidence is absent.

kaigi evidence-package "embodied agency" --out evidence.json --best-effort

監査可能な根拠packageを作る Create an auditable evidence package

contextと同じ有界検索結果へ根拠IDを付け、完全性、payloadとpackageのSHA-256、外部未送信のreceiptをローカルに保存します。元ファイルpath、Finder bookmark、PDF binaryは含みません。CLIはモデルを起動・送信しないため、外部モデルへ渡す操作は利用者が別途許可します。 Runs the same bounded retrieval as context, then writes local evidence IDs, completeness, payload/package SHA-256 hashes, and a receipt confirming no external transmission. It excludes source paths, Finder bookmarks, and PDF bytes. The CLI does not launch or contact a model; sending the package requires separate user authorization.

kaigi documents research-context "embodied agency" --limit 8 --max-blocks-per-document 16 --best-effort

文献を横断 Search the literature set

kAIgiで本文を抽出済みの文献を語句で順位付けし、関連度の高い文書、根拠段落、文書ノート、自分のコメントを1つの有界なJSONへまとめます。document_note_scope.source_evidence は false なので、自由な考察を引用根拠と取り違えません。scan_complete、truncated、limitations を確認してから、見つからないという結論を出します。 Lexically ranks papers whose text kAIgi has extracted and returns a bounded JSON set of relevant documents, evidence passages, document notes, and source-bound annotations. document_note_scope.source_evidence is false, preventing freeform thinking from being mistaken for citable evidence. Check scan_complete, truncated, and limitations before concluding that evidence is absent.

kaigi documents list --limit 20 --best-effort

文書を探す Find a document

documents search "query" と組み合わせ、タイトル、識別子、抽出済み本文から対象文書を絞り込みます。元PDFのパスやバイナリは返しません。 Combine with documents search "query" to find a document by title, identity, or extracted text. Source PDF paths and bytes are never returned.

kaigi documents context <document-id> --pages 3-8 --include text,structure,annotations

必要なページを精読 Read selected pages closely

横断検索で選んだ文書から、必要なページと要素だけを読み取り専用で取得します。annotations を含めると、文書全体への自分の考察は document_note、本文に結び付く記述は annotations として分かれます。ページ、段落ID、本文ハッシュ、抽出の完全性、省略状態も保つため、引用候補を元の版へ戻して確認できます。 Reads only the selected pages and components from a shortlisted document. When annotations is included, document-wide thinking appears as document_note, while source-bound writing remains in annotations. Page, block ID, source hash, extraction completeness, and truncation state stay attached so candidate citations can be checked against the exact revision.

kaigi recordings list --limit 20 --best-effort

録音を探す Find recordings

録音タイトル、日時、長さ、音声・文字起こしの有無を一覧します。古い録音の一部が読めない場合も、ロック確認を保ったまま理由と件数を返します。 Lists recording titles, dates, durations, and whether audio and transcripts exist. If legacy sessions cannot be read, it keeps the lock checks and reports reason/count metadata.

kaigi recordings inspect <recording-id> --max-segments 500

全文を確認 Inspect a transcript

選んだ録音の文字起こしを、話者・時刻・確度と一緒に確認します。 Inspects the selected transcript with speakers, timing, and confidence.

kaigi recordings search "query" --limit 20 --best-effort

録音内を検索 Search transcripts

録音のタイトルと文字起こしから、該当する録音を絞り込みます。--best-effort は読めない録音を止めずに件数で知らせます。 Searches recording titles and transcript text. --best-effort reports inaccessible recordings by count instead of aborting discovery.

kaigi recordings export <recording-id> --out "$working"

編集用に取り出す Create a working copy

録音IDと元データのハッシュを含む、録音に紐づいた編集用コピーを作ります。直接ファイルを編集しません。 Creates a recording-bound working copy with the recording ID and source hash. Do not edit the canonical files directly.

kaigi recordings validate-transcript <recording-id> --in "$working"

反映前に検証 Preflight corrections

録音が変わっていないか、文字だけの修正か、何セグメント変わるかを確認します。kAIgiの正式データは変更しません。 Checks the source hash, text-only contract, and exact changed-segment count without modifying kAIgi.

kaigi recordings apply-transcript <recording-id> --in "$working"

修正をkAIgiへ反映 Apply corrections

文字だけの修正を検証し、kAIgiの正式データへ安全に反映します。別の変更が先に入っていれば、古いコピーとして拒否します。 Validates text-only corrections and safely applies them to kAIgi. A stale working copy is rejected if another change landed first.

kaigi recordings postprocess prepare <recording-id> --out "$candidate"

外部後処理の候補を準備 Prepare an external postprocessing candidate

現在の文字起こしに結び付いたtext-only候補を作ります。CLIは5.6 Solを推奨モデルとして示しますが、モデルを起動せず、データも送信しません。外部エージェントへ渡す操作と送信範囲は利用者が別途許可します。 Creates a text-only candidate bound to the current transcript. The CLI recommends 5.6 Sol but neither launches a model nor transmits data; the user separately authorizes any handoff and its scope.

kaigi recordings postprocess review <recording-id> --in "$candidate" --out "$review"

全変更を差分review Review every proposed text change

候補内の全テキスト変更をbefore／afterで列挙し、候補とreviewのSHA-256を返します。省略された差分がないことを確認してから、表示された review_sha256 を使います。 Lists every text change as before and after values and returns candidate and review SHA-256 hashes. Inspect the complete diff before using the displayed review_sha256.

kaigi recordings postprocess apply <recording-id> --in "$candidate" --review "$review" --review-sha256 HASH

確認した差分だけを反映 Apply only the acknowledged review

指定したreview SHA-256と現在の候補・review・録音を再検証してから原子的に反映します。確認後にいずれかが変わっていれば、安全に停止します。 Revalidates the acknowledged review SHA-256, candidate, review bytes, and current recording before atomic publication. Any post-review change stops safely.

kaigi recordings discussion-log export <recording-id> --out "$context"

議論ログの材料を取り出す Export discussion-log context

全文、録音ID、文字起こしハッシュ、発話列、現在の議論ログを、エージェントが後処理できる作業用JSONとして取り出します。元の録音データは変更しません。 Exports the full transcript, recording ID, source hash, utterance list, and current discussion log as a working JSON for an agent. It does not change the recording.

kaigi recordings discussion-log validate <recording-id> --in "$context"

議論ログを反映前に検証 Validate a discussion log

discussion_logのスキーマ、発話の完全一致、セグメントの連続被覆、議題ブロック、録音ハッシュを確認します。正式データは変更しません。 Checks the discussion_log schema, exact utterance identity, contiguous segment coverage, topic blocks, and recording hash without changing canonical data.

kaigi recordings discussion-log apply <recording-id> --in "$context"

議論ログを反映 Apply a discussion log

検証済みの議論ログだけを、セッションの排他的ロック下で discussion_log.json へ原子的に反映します。文字起こしが先に変わっていれば古い作業コピーとして拒否します。 Publishes only the validated discussion log to discussion_log.json under the session's exclusive lock. It rejects a stale working copy if the transcript changed first.

kaigi transcribe /path/to/audio.m4a --quality accurate --out /tmp/kaigi-transcription.json

音声ファイルを文字起こし Transcribe an audio file

外部音声ファイルを端末内で文字起こしします。結果は独立したJSONで、録音一覧へは自動追加しません。 Transcribes an external audio file on this Mac. The result is a standalone JSON file and is not added to the recording library automatically.

Two-pass refinement

高精度化は2段階 Refine in two passes

1. 確度の低い箇所から 1. Start with low confidence

needsReview または確度 0.70 未満を、前後の発話・固有名詞・繰り返し表現と照合して直します。確信できない部分は残します。 Review needsReview segments or confidence below 0.70 using nearby speech, names, and repeated terms. Leave uncertain wording unchanged.

2. 全体の文脈で整える 2. Normalize with full context

全文を読み直し、名前・製品名・専門用語・句読点・文の切れ目を、意味が変わらない範囲で一貫させます。要約や発話の追加はしません。 Re-read the full transcript and normalize names, products, technical terms, punctuation, and sentence boundaries without changing meaning. Never summarize or add speech.

3. 検証して一度だけ反映 3. Preflight, then apply once

2段階が終わったら validate-transcript で変更件数を確認し、その後に apply-transcript を一度だけ実行します。反映後は新しいパスへ再度exportし、意図した変更だけか確認します。 After both passes, check the change count with validate-transcript, then run apply-transcript once. Export to a new path afterward and verify that only the intended text changed.

プライバシーの確認 Privacy check

CLI自体は音声、文字起こし、抽出済みPDF本文をこのMac上で読み取ります。ただしCodexやClaude Codeへ依頼した場合、選択したモデルと設定によってはCLIの出力がモデル提供元へ送られます。kAIgiはCLIの初回インストール時に警告しますが、現行CLIはコマンドごとの確認を行いません。統合 context、録音の inspect・search・export・apply-transcript・postprocess・discussion-log、文書の search・research-context・context・inspect は文字起こし本文、抽出本文、文書ノート、または指定したコメントを扱います。文書ノートは自分の考察であり、原文の引用根拠ではありません。 The CLI itself reads audio, transcripts, and extracted PDF text on this Mac. When you ask Codex or Claude Code to use it, however, CLI output may be sent to the selected model provider under that agent's settings. kAIgi warns when the CLI is installed for the first time, but the current CLI does not confirm every command. Unified context, recording inspect, search, export, apply-transcript, postprocess, and discussion-log, plus document search, research-context, context, and inspect, handle transcript text, extracted text, document notes, or requested annotations. Document notes are your own thinking, not citable source evidence.

AI Researchの外部Web検索はCLIとは別の通信経路です。詳しくはプライバシーポリシーを確認してください。 AI Research web search is a separate transmission path from the CLI. See the Privacy Policy for details.
