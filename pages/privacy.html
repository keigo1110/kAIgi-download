kAIgi Privacy Policy kAIgi Privacy Policy

kAIgiは会議音声、Textで開くPDF、Recall、AI Researchを扱うアプリです。録音対象、保存場所、端末内処理、任意の外部送信について、ユーザーが判断できるように説明します。 kAIgi handles meeting audio, PDFs opened in Text, Recall, and AI Research. This policy explains what is recorded, where data is stored, what runs on device, and when external services may be used.

Last updated: 2026-08-26

保存するデータ Data stored by kAIgi

kAIgiは、ユーザーが録音を開始したセッションについて、Mac上で再生されている内部音声、マイク音声、単語時刻を含む文字起こし、任意の話者解析結果、AI Researchのカード、議論ログ、セッションメタデータを保存します。話者解析結果にはセッション内の話者区間、表示名、モデル版が含まれます。議論ログ（discussion_log.json）はセッションフォルダ内に保存され、確定済み発話テキストの複製、Mac上のLocal LLMが生成した話題の区切り・タイトル・要約・議題ブロック・成果ラベルを含みます。議論ログの生成はすべてMac上で行われ、外部へ送信されません。これらは標準では ~/Documents/KAIgiRecordings に保存されます。 For sessions started by the user, kAIgi stores system audio, microphone audio, transcripts with word timing, optional speaker-analysis results, AI Research cards, a discussion log, and session metadata. Speaker-analysis results include per-session speaker intervals, display names, and the model version. The discussion log (discussion_log.json) is stored inside the session folder and contains a copy of the finalized utterance text plus topic boundaries, titles, summaries, topic blocks, and outcome labels generated by the on-device Local LLM; discussion-log generation happens entirely on this Mac and is never transmitted externally. By default, these files are stored in ~/Documents/KAIgiRecordings.

kAIgiは録音フォルダのPOSIX権限を現在のmacOSユーザー専用（0700）へ狭め、旧版で作成した録音フォルダも履歴の読み込み時に修復します。これは同じmacOSユーザーとして実行される他のアプリやプロセスからデータを隔離する仕組みではありません。 kAIgi narrows the recordings folder's POSIX permissions to the current macOS user (0700) and repairs a recordings folder created by an older version when history is loaded. This does not isolate the data from other apps or processes running as the same macOS user.

Local LLMのモデル、再利用用Research Memory、手動登録または自動学習した音声認識語は ~/Library/Application Support/kAIgi に保存されます。Research Memoryには、マスキングした検索論点、生成済みカード、参照した情報源とフィードバックが含まれることがあります。Research Cardは既定では自動削除しません。ユーザーが30、90、180、365日のいずれかを明示的に選んだ場合だけ、作成日が期限を超えたピン留めされていないカードを自動削除します。設定がない、未知、または破損している場合は無期限保持になります。カードを自動再利用するための種類別鮮度は物理削除とは別で、鮮度を過ぎてもカードはLibraryに残ります。生成履歴と情報源の再利用キャッシュは派生データとして30日で整理します。清掃は起動時と通常1日1回試行し、一時的に清掃だけが失敗した場合は通常の利用を妨げず15分以上あけて再試行します。 Local LLM models, reusable Research Memory, and manually saved or automatically learned speech-recognition terms are stored in ~/Library/Application Support/kAIgi. Research Memory may include masked research prompts, generated cards, referenced sources, and feedback. By default, Research Cards are not deleted automatically. Only when the user explicitly selects 30, 90, 180, or 365 days does kAIgi automatically delete unpinned cards whose creation date is beyond that period. A missing, unknown, or damaged setting resolves to indefinite retention. Type-specific freshness for automatic reuse is separate from physical deletion; a stale card remains available in the Library. Generation records and the source-reuse cache are derived data and are cleaned after 30 days. Cleanup is attempted at startup and normally once per day. If cleanup alone fails temporarily, normal use continues and cleanup is retried after at least 15 minutes.

PDFとTextデータ PDFs and Text data

Textで開いた元PDFはFinderの場所に残り、kAIgiはPDFを複製しません。kAIgiは再接続用ブックマークとファイル識別情報に加え、文書履歴、抽出本文、翻訳、生成した構造、コメント、読書位置、プロジェクト情報を ~/Library/Application Support/kAIgi/Text に分離して保存します。Finderから元PDFを削除しても、このTextデータは削除されず、保存済み本文はRecall、Zoom、文書内検索で引き続き使われます。元ページを表示する操作だけはPDFの再接続が必要です。 A source PDF opened in Text remains at its Finder location; kAIgi does not duplicate it. Separately, kAIgi stores a reconnection bookmark and file identity together with document history, extracted text, translations, generated structure, comments, reading position, and project information under ~/Library/Application Support/kAIgi/Text. Deleting the source PDF in Finder does not delete this Text data. Stored text remains available to Recall, Zoom, and in-document search; only operations that display the source page require reconnection.

同じバイト列のPDFを再び開くと、SHA-256による完全一致を確認して以前の履歴へ自動で再接続します。DOI、arXiv識別子、タイトル、本文の近さ、以前と同じFinder位置は、「同じ論文の別版かもしれない」という比較候補を作るためだけに使います。これらの弱い一致だけで自動統合せず、ユーザーが新旧を確認してリンクまたは別文書を選びます。別版へリンクした場合も、翻訳は原文が一致する文だけを再利用し、構造と抽出本文は現在のPDFに一致するまで表示しません。コメントの根拠を再発見できない場合は、未解決として残します。 When the exact PDF bytes are opened again, kAIgi verifies their SHA-256 and automatically reconnects the previous history. A DOI, arXiv identifier, similar title or text, or the same former Finder location is used only to propose that a file may be another revision of the same paper. These weaker matches never merge records automatically; the user compares both and chooses whether to link or keep a separate document. Even after linking a revision, a translation is reused only for a sentence whose source text still matches, and structure or extracted text stays hidden until it matches the current PDF. Comments whose evidence cannot be found remain visible as unresolved.

「Textデータを書き出す」は、文書履歴、抽出本文、翻訳、構造、コメント、Textプロジェクトを1つの .kaigitextbackup ファイルへ保存します。元PDF、Finderの場所、再接続用ブックマーク、録音、APIキーは含みません。読み込みでは、ファイル形式・容量・各データ・完全性を既存データの変更前に検証し、文書ごとに追加・完全一致への統合・読み込まない、の許可された選択肢を表示します。確定時にもバックアップと現在のライブラリを再確認し、準備したライブラリ全体を一度に置き換えます。通常の失敗で既存Text履歴を部分更新しません。バックアップには抽出本文やコメントなどの内容が入るため、ユーザーは保存先と共有相手を管理し、不要になった書き出しファイルをFinderから削除する必要があります。 Export Text Data stores document history, extracted text, translations, structure, comments, and Text projects in one .kaigitextbackup file. It excludes source PDFs, Finder locations, reconnection bookmarks, recordings, and API keys. Before changing existing data, import validates the format, size, every artifact, and overall integrity, then shows the allowed per-document choices: add, merge an exact match, or skip. At confirmation, kAIgi rechecks both the backup and the current library and publishes one prepared library generation. An ordinary failure does not partially update the existing Text history. Because the backup contains extracted text, comments, and other content, users must control where it is stored and shared and delete an unneeded exported file in Finder.

文字起こし Transcription

文字起こしにはApple Speechのオンデバイス認識を使用します。選択した認識言語は次の録音開始時に固定され、言語ごとの辞書を使用します。クラウドSTT APIへの自動フォールバックは行いません。認識経路の改善に使うため、完了セッション数、SpeechAnalyzerで認識を実際に試行したセッション数、fallbackが発生したセッション数と理由別件数だけを端末内へ保存します。fallback率はSpeechAnalyzerを試行したセッションだけを分母にします。この集計には音声、文字起こし本文、Appleの詳細エラー文を含めず、外部へ送信しません。 kAIgi uses Apple Speech on-device recognition for transcription. The selected recognition language is fixed when the next recording starts and uses a language-specific dictionary. kAIgi does not automatically fall back to a cloud speech-to-text API. To improve recognition routing, kAIgi stores only local aggregate counts for completed sessions, sessions that actually attempted recognition with SpeechAnalyzer, sessions that used fallback, and fallback reasons. The fallback rate uses only SpeechAnalyzer-attempted sessions as its denominator. This aggregate does not contain audio, transcript text, or Apple's detailed error text and is not sent externally.

Recall（連想検索） Recall associative search

Recallは、保存済み文字起こしとTextで抽出済みのPDF本文から、詳細検索用の索引をMacのメモリ上に作ります。検索語、検索履歴、検索語のベクトル、検索結果は保存せず、Core Spotlightにも登録しません。Semantic Zoomを次回すばやく開くため、再生成可能な派生Atlasを ~/Library/Application Support/kAIgi/Recall に保存します。Atlasに含むのは、元資料の安定IDと改訂、埋め込みモデルの版と次元、資料ごとの正規化ベクトル、有限のカテゴリ／クラスID、短い集約ラベルと件数です。文字起こし本文、PDF本文、引用、翻訳文、資料ごとのタイトル、プロジェクト名・色・アイコン、検索語、検索順位、元資料を開く位置、画面座標はAtlasへ保存しません。kAIgiはRecallの検索語や元データ本文をkAIgiが運用するサーバーまたは外部検索サービスへ送信しません。 Recall builds its detailed search index in memory from saved transcripts and PDF text already extracted in Text. It does not persist queries, query history, query vectors, or search results, and it does not donate content to Core Spotlight. To reopen Semantic Zoom quickly, kAIgi stores a regenerable derived atlas under ~/Library/Application Support/kAIgi/Recall. The atlas contains stable source IDs and revisions, the embedding model revision and dimension, one normalized vector per source, finite category and class IDs, short aggregate labels, and counts. It does not store transcript text, PDF text, quotations, translations, per-source titles, project names, colors or icons, queries, result rankings, source-opening locations, or screen coordinates. kAIgi does not send Recall queries or source text to a kAIgi server or an external search service.

対応するMacでは、AppleのオンデバイスContextual EmbeddingとApple Translationを使い、意味の近さと日本語・英語間の検索およびSemantic Zoomを補助します。検索では長さを制限した検索語または関連検索の起点を、Atlas作成では各資料から選んだ最大600文字の代表文を一時的に翻訳することがあります。文字起こしやPDF本文全体を翻訳せず、翻訳文も保存しません。必要な言語データがない場合、macOSが許可を求めてデータをダウンロードすることがあります。Appleはフレームワークのポリシーに基づき、本文ではないサービスメタデータを収集する場合があります。機能を利用できない時も語句による検索は動作します。 On supported Macs, Apple on-device Contextual Embedding and Apple Translation assist meaning-based and Japanese–English retrieval and Semantic Zoom. Search may temporarily translate a bounded query or related-search seed; atlas construction may temporarily translate a representative passage of up to 600 characters selected from each source. kAIgi does not translate the full transcript or PDF corpus and does not persist translations. If language assets are missing, macOS may ask permission to download them. Apple may collect non-content service metadata under its framework policy. Lexical search remains available when these enrichments are unavailable.

検索結果から元データを開く時は、現在の文字起こしまたはPDFを読み直し、検索時と同じ版か確認します。元データが変更または削除されている場合、古い位置へそのまま移動しません。 Before opening a result, kAIgi rereads the current transcript or PDF and verifies that its revision still matches the search result. If the source was changed or removed, kAIgi does not silently navigate to the stale location.

話者分離 Speaker diarization

話者分離を有効にし、設定で明示的にモデルをダウンロードすると、録音停止後にFluidAudioとFluidInferenceのCore MLモデルを使ってMac上でシステム音声を解析します。モデル取得時は huggingface.co へ接続しますが、会議音声や文字起こしはモデル提供元へ送信しません。モデルは ~/Library/Application Support/kAIgi/Models/SpeakerDiarization に保存され、設定から削除できます。モデルの提供元、固定版、ライセンスはリポジトリのThird-party on-device models文書に記載します。 When speaker diarization is enabled and the user explicitly downloads its model in Settings, kAIgi analyzes system audio on the Mac after recording stops using FluidAudio and a FluidInference Core ML model. Downloading connects to huggingface.co, but meeting audio and transcripts are not sent to the model provider. The model is stored under ~/Library/Application Support/kAIgi/Models/SpeakerDiarization and can be deleted in Settings. Provider, pinned revision, and license details are recorded in the repository's Third-party on-device models document.

解析時は、FluidAudioとCore MLへ安全な固定パスを渡すため、検証済みモデルの一時スナップショットを ~/Library/Application Support/kAIgi/Models/SpeakerDiarizationRuntime 内に作成します。これは同じMac上だけで行うCopy-on-Write複製または上限付きコピーで、外部への送信ではありません。連続する解析で同じ検証済みモデルを再利用するため、解析終了後もアプリの起動中に最大4件（通常の同じ保存先では1件）の待機スナップショットを保持することがあります。待機中は使用ロックを解放し、次回使用前にモデルと保存先が同じ世代かを再検証します。不一致、保持上限の超過、正常終了、またはモデル削除時には、現在の管理対象保存先にあり所有権を安全に確認できる待機スナップショットを削除します。クラッシュなどで管理対象保存先に残ったスナップショットは、次回の話者解析またはモデル削除時に回収します。設定からのモデル削除は、実行中の解析が終了し、保存モデルと管理対象保存先の一時スナップショットをすべて安全に削除できた時点でのみ完了と表示します。完全な削除を確認できない場合は成功と表示しません。同じユーザーまたは同じユーザー権限の別プロセスが管理対象保存先の外へ移動・複製したモデルは、手動で書き出したファイルと同様に自動削除の対象外です。 During analysis, kAIgi creates a temporary snapshot of the verified model under ~/Library/Application Support/kAIgi/Models/SpeakerDiarizationRuntime so FluidAudio and Core ML receive a stable, controlled path. This is a same-Mac copy-on-write clone or bounded copy, not an external transmission. To reuse the same verified model across consecutive analyses, kAIgi may keep up to four idle snapshots while the app process is running (normally one for the same storage location). An idle snapshot releases its usage lock and is revalidated against the model and storage generations before reuse. When validation fails, the retention bound is exceeded, the app terminates normally, or the model is deleted, kAIgi removes idle snapshots whose ownership can still be proved safely inside the current managed location. Managed snapshots left there by a crash are recovered during a later diarization attempt or model deletion. Deletion from Settings is shown as complete only after active analysis has finished and both the installed model and all temporary snapshots in the managed location have been safely removed. kAIgi does not report success when complete deletion of that managed location cannot be verified. A model moved or copied outside the managed location by the same user or another process running as that user is outside automatic deletion, like any manually exported file.

kAIgiは声紋embeddingや会議横断の話者データベースを保存しません。保存する話者IDはセッション内だけで有効です。マイクを既定で「あなた」と表示しますが、会議室で複数人が同じマイクを使う場合などに備え、マイクを含む表示名をユーザーが変更できます。時刻が欠ける、重なる、または対応しない語は単一話者へ推測せず、重なりまたは話者不明として表示します。 kAIgi does not store voice embeddings or a cross-meeting speaker database. Stored speaker IDs are valid only within one session. The microphone defaults to “You,” but users can rename it and other speakers, including when several people share a room microphone. Words with missing, overlapping, or unmatched timing are shown as overlap or unknown rather than guessed as one speaker.

AI ResearchとOpenAI連携 AI Research and OpenAI

AI Research機能を有効にした場合、簡易マスキングした直近の文字起こしと検索論点をOpenAI APIへ送信することがあります。この処理は完全な匿名化ではなく、敬称のない人名、社名、住所、文脈依存の固有名詞を検出できない場合があります。この機能は任意であり、ユーザーが設定したOpenAI API keyを使用します。API keyはmacOS Keychainに保存されます。利用モデルはkAIgiの既定値を使用し、ユーザーがアプリ内でモデルを選択する必要はありません。 When AI Research is enabled, kAIgi may send lightly masked recent transcript context and research prompts to the OpenAI API. This is not complete anonymization and may miss names without honorifics, company names, addresses, and context-specific proper nouns. This feature is optional and uses the OpenAI API key entered by the user. The API key is stored in macOS Keychain. kAIgi uses its default model configuration; users do not need to choose models in the app.

会議参加者への通知 Notifying meeting participants

会議、通話、対面の会話を録音する場合は、録音を開始する前に参加者へ通知し、必要な同意を得てください。録音に関する法令や社内ルールは地域や組織により異なります。 Before recording a meeting, call, or in-person conversation, notify participants and obtain any required consent. Recording rules vary by location and organization.

データの削除 Deleting data

保存済みの録音、文字起こし、話者区間と変更した話者名、セッション内のAI Research結果、議論ログは、履歴をゴミ箱へ移動するかFinderから該当セッションフォルダを削除することでまとめて削除できます。Recallの詳細検索索引と検索状態はメモリ上だけにあり、アプリ終了時に消えます。派生Atlasは、元のAudio／PDFが削除されたことを権威ある台帳で確認した後に対応する資料を自動で除外します。Atlas全体だけを削除する場合は、kAIgiを終了してからFinderで ~/Library/Application Support/kAIgi/Recall を削除できます。元のAudio／PDFには影響せず、次にSemantic Zoomを開いた時に必要な分を再生成します。設定の「端末内Researchデータ」は議論ログやRecall Atlasを削除しません（議論ログはResearch Memoryではなくセッション内データです）。「音声だけ削除」は音声ファイルだけを削除し、文字起こしと話者解析結果は残します。設定の「端末内Researchデータ」はResearch Memoryと全言語の自動学習語を削除しますが、録音セッション内の話者解析結果は削除しません。Research Libraryでは再利用用カードを個別に削除でき、手動登録した音声認識語は各言語の辞書から個別に削除できます。STT診断の端末内集計は録音データ設定の「診断データを削除」から、Local LLMモデル、話者分離モデル、OpenAI API keyはそれぞれ設定から削除できます。話者分離モデルの削除完了には、実行中の解析が終了し、管理対象の一時スナップショットも安全に削除されていることが必要です。 Saved audio, transcripts, speaker intervals and edited speaker names, per-session AI Research results, and the discussion log can be removed together by moving the history item to Trash or deleting its session folder in Finder. Recall's detailed search index and search state exist only in memory and disappear when the app quits. After an authoritative Audio/PDF catalog confirms that a source was deleted, the derived atlas automatically excludes its corresponding entry. To remove only the complete atlas, quit kAIgi and delete ~/Library/Application Support/kAIgi/Recall in Finder. This does not affect the source Audio/PDF data; kAIgi regenerates required atlas entries when Semantic Zoom is opened again. “On-device Research Data” does not delete discussion logs or the Recall atlas — discussion logs are per-session data, not Research Memory. “Delete audio only” removes only audio files and leaves the transcript and speaker-analysis result. “On-device Research Data” deletes Research Memory and automatically learned terms for every language, but it does not delete per-session speaker-analysis results. Reusable cards can be deleted individually in the Research Library, and manually saved recognition terms can be removed from each language's dictionary. The STT diagnostics aggregate can be removed with Delete Diagnostics under Recording Data; Local LLM models, the speaker-diarization model, and the OpenAI API key can each be deleted in Settings. Speaker-model deletion completes only after active analysis has finished and all managed temporary snapshots have also been removed safely.

Textの更新履歴で削除を選ぶと、その文書の抽出本文、翻訳、構造、コメント、読書状態を含むkAIgi独自データをゴミ箱へ移し、Finder上の元PDFは残します。反対に、Finderで元PDFだけを削除してもkAIgi独自データは残ります。kAIgiが書き出した .kaigitextbackup はユーザーが選んだ場所にある独立ファイルであり、元のText履歴を削除しても自動では削除されません。 Deleting an item from Text Updates moves kAIgi's companion data for that document—including extracted text, translations, structure, comments, and reading state—to Trash while leaving the source PDF in Finder. Conversely, deleting only the source PDF in Finder leaves the companion data in kAIgi. An exported .kaigitextbackup is an independent file at the location chosen by the user and is not automatically removed when the original Text history is deleted.
